## What this is

The behavioral criteria **A1–A11** are provable only by **running** the new orchestrator
`/build`, which a `/build` cannot do to itself. So the orchestrator was run against the
throwaway 6-task validation plan in a **separate window** (window B) on a throwaway
branch, and the A1–A11 observations were **fed back to the paused build session** (window
A), which — as sole committer and sole `[x]` authority — records them here and marks the
plan. The run's own sandbox commits live only on the discarded harvest branch; **this doc
is the proof that survives.**

All observations below are **observed, not inferred** — each cites the transcript event
that produced it.

## A10 falsification result (the criterion easiest to fake — proven honest)

The end-of-batch review exercised the **real**
`temps.append_reading(100) → readings.csv → report.flag_dangerous()` path and ran the
plan's mandated falsification test:

| Condition                                         | Boiling `100` flagged? | Integration                  |
| ------------------------------------------------- | ---------------------- | ---------------------------- |
| Mismatch present (report threshold `>211` °F)     | **No — danger missed** | 🔴 RED                       |
| Mismatch removed (units aligned, threshold `>99`) | Yes                    | 🟢 GREEN                     |
| Per-task `check_temps` / `check_report`           | —                      | 🟢 GREEN **both directions** |

Red→green at **integration** scope with the **unit checks unmoved in both directions** is
the signature of an honest cross-task fault: a genuinely boiling `100` °C reading is read
as `100` °F, falls below `211`, and the danger is silently missed — invisible to both
per-task verifiers, caught only by the cross-task review. **A10 is real, not faked.**

## The surrogation tell (watched per the residual-risk note)

The design spec's named residual risk was **surrogation recursion** — "did it pass?"
replacing "is it right?" at the end-of-batch review. On this run the review did **not**
rubber-stamp the green: it re-derived the A10 fault from the real integration path rather
than re-reading the per-task gates, and it pulled the `(manual)`/shallow-proxy items out
of the green rather than folding them in. The tell did not fire on this run. (One run is
not a guarantee — the risk stays on the record for future runs.)
